Part 4

The model

Depth Anything V2 Small, adapted to predict absolute height in metres with a per-pixel uncertainty. Every layer, every parameter count, and every initialisation decision.

4.1 What the base model is

Identifier

Licence
Apache-2.0. This is the only variant that can legally ship. Base, Large and Giant are CC-BY-NC-4.0.

Monocular relative depth estimation on natural, ground-level photographs.
Backbone
DINOv2 ViT-S — a vision transformer, patch size 14, embedding dimension 384.
Neck
DPT — Dense Prediction Transformer. Reassembles the coarse token grid back into a dense per-pixel feature map.

What each of those words means

Vision transformer
A network that cuts an image into a grid of small squares (“patches”), turns each into a vector (“token”), and lets every token exchange information with every other token. Unlike a convolutional network it has a global view from the first layer.
Patch size 14
Each square is 14×14 pixels. This single number constrains everything downstream — see the input-size trap in 4.5.
Embedding dimension 384
Each 14×14 patch is represented by a vector of 384 numbers.
DINOv2
A backbone trained with self-supervision — no human labels at all. It learned general visual structure from a very large image collection, which is why it transfers to imagery it never saw, including satellite photographs.
DPT
The decoder design that takes transformer tokens at several depths and progressively fuses and upsamples them into a full-resolution prediction.

Almost all of the learned knowledge — 89% of it — lives in a backbone that was downloaded, not trained here. The part that was designed for this problem is 0.1% of the parameters. That is not a weakness; it is the entire point of fine-tuning a foundation model. 4.3 The four changes made to the stock model

Change 1 — two outputs instead of one

The stock head ends in a single 32→1 convolution. That convolution is kept and becomes the mean branch (conv_mu), because its weights are pretrained and worth keeping. A second 1×1 convolution is added as the log-variance branch (conv_log_var). Both share conv1 and conv2.

This is the standard Kendall & Gal arrangement for heteroscedastic uncertainty: one trunk, two thin heads, one predicting the value and one predicting how uncertain that value is. It costs almost nothing.

Change 2 — no final ReLU

The stock head clamps its output at zero, because relative depth cannot be negative. Height above ground is almost non-negative — but a hard ReLU has zero gradient everywhere it is active, so any pixel the model pushes below zero early in training is dead for the rest of the run. The ReLU is removed and the loss is left to handle plausibility.

Change 3 — output scaled to metres

The pretrained head emits values around 1. Height above ground runs to tens or hundreds of metres. Rather than force the head to learn a large gain through a 5×10-6 learning rate, the network predicts in normalised units and the result is multiplied by height_scale.

height_scale = 13.223477220535276

This is not a round number and not a guess. It is the 95th percentile of the above-ground height distribution measured across all 2,783 training tiles. The maximum would be wrong — that is a lone 204 m structure, and scaling by it would squash every ordinary building toward zero. The p95 puts the bulk of the distribution in a sensible numeric range.

The loss therefore sees metres directly, which means the RMSE printed during training is already the number ISRO scores, while the network's internal range stays around 1.

Variance is predicted in the same normalised units, so converting it to metres is a shift of 2·log(height_scale) in log space. Doing that inside the model rather than inside the loss keeps the loss unit-agnostic and the reported σ in metres.

Change 4 — a useful accident of polarity

Depth Anything V2 predicts inverse relative depth: nearer is a larger number. Viewed from orbit, nearer means taller. So the pretrained head's sign convention already matches height, and the fine-tune starts from a sensible initialisation rather than fighting one.

4.4 Initialisation, and why each choice is deliberate

conv_log_var weights
Initialised to zero, bias to 2·log(init_sigma / height_scale) with init_sigma = 5.0 m. So σ starts uniform at 5 m everywhere and only becomes spatially varying once the data gives it a reason to. Random initialisation here lets the variance term shove the mean head around before the mean head knows anything.
conv_mu, default
init_mu="pretrained" — keeps the pretrained readout. This is what runs 01–04 used, and keeping it as the default means those runs stay bit-comparable.
conv_mu, alternative
init_mu="constant" — zero the weights and set the bias to a chosen constant height. Added after run05 died. See below.
The initialisation bug that cost nine GPU-hours

The pretrained readout emits disparity, and its output scale is a property of the checkpoint's feature magnitudes, not of the task. Measured on real crops with tools/preflight.py: the median absolute residual at initialisation is 16.5 m for DA-V2-Small but 666 m for DA-V1-Large. The two model families' necks do not emit features of the same magnitude, even though their conv3 weights are comparable in size (mean |w| 0.088 against 0.100).

A 666 m residual drives log_var into its clamp on the very first NLL step. The clamp then zeroes the variance head's gradient and suppresses the mean head's by roughly 1,100× (measured by tools/nll_deadlock_probe.py). That is what killed run05: it diverged to NaN at epoch 6 and produced no information at all. The fix is init_mu="constant", which discards a 32→1 linear readout of disparity that would have to be relearned as height anyway, while keeping the backbone, the neck and conv1/conv2.

4.5 The input-size constraint — a trap that fails silently

Patch size 14 governs every image dimension in this project

The head computes patch_h = H // 14 and then interpolates its output to patch_h × 14. Feed it a 256×256 crop — the size the Depth Any Canopy recipe uses — and you get 252×252 back, with no warning and no error.

Crops are therefore 518, which is 14 × 37 and is also DA-V2's native training resolution. A stride of 506 tiles a 1024×1024 image exactly 2×2. model.check_input_size() raises a ValueError naming the nearest valid sizes rather than letting a mismatch reach the loss, where it would surface as a confusing broadcast error or, worse, silently work after an accidental resize.

4.6 The forward pass, in order

1.  check_input_size(H, W, 14)                     raise if not a multiple of 14
2.  ph, pw = H // 14, W // 14                       token grid dimensions
3.  out = backbone.forward_with_filtered_kwargs(x)  DINOv2 ViT-S -> feature maps
4.  hidden = neck(out.feature_maps, ph, pw)         DPT reassemble + fuse
5.  feat = hidden[head_in_index]                    head_in_index = -1, the last stage
6.  x = conv1(feat)                                 64 -> 32 channels
7.  x = interpolate(x, (ph*14, pw*14), bilinear)    upsample, exactly as in the DPT paper
8.  x = activation1(conv2(x))                       32 -> 32, ReLU
9a. mu      = conv_mu(x) * height_scale             metres
9b. log_var = conv_log_var(x) + 2*log(height_scale) log-variance in metres-squared
10. return mu, log_var

model.predict() wraps this, converts log-variance to sigma = exp(0.5 · log_var), and returns (height_m, sigma_m) as two (B, 1, H, W) tensors.

4.7 The optional binned head (built, measured, not shipped)

A second head design exists behind --bins N, defaulting to 0 (off). It implements the architecture from HTC-DC Net, IEEE TGRS 2023:

Adaptive bins
A small MLP over the pooled feature map predicts N bin widths per image via softmax, so widths are strictly positive and always sum to the full height range. Edges are the cumulative sum from bin_min.
Soft-argmax
The output is the expectation H = Σ Pᵢcᵢ over bin centres — a continuous value from a classification head, with no discretisation artefacts.
Head-tail cut
Foreground is defined as height > 1 m. Foreground and background get their own distribution over bins, selected per pixel by a binary classifier. Measured on our shards, 35.6% of valid pixels sit above 1 m, so the binary problem is close to balanced.
Warmup routing
During the first 500 steps the ground truth does the routing, not the gate. Measured at initialisation, a randomly initialised gate fired on either 0.0% or 99.4% of pixels depending on the random projection — whichever branch loses gets no gradient at all. Truth-routing removes that lottery.
Configuration
N = 128 bins over a measured range of [−3, 120] m. 128 rather than the conventional 256 because ablations show gains saturate early and 128 is what fits in 12 GB at 518×518.

It lost. run03 scored 6.950 m whole-tile against run02's 6.454 m — 7.7% worse overall and 8.8% worse on buildings, which is the thing it was built to fix. The full result is in Part 13. The code is kept because it exports to ONNX cleanly and is the right starting point if the approach is revisited.

The backbone is a well-conditioned pretrained representation and wants the small rate the Depth Any Canopy recipe uses. The head is doing something the pretrained weights were never asked to do — emit metres, and emit a variance from a freshly initialised convolution — so it needs a materially larger rate or it spends the whole budget catching up. Excluding biases and normalisation parameters from weight decay is standard practice for vision transformers.

4.9 Reconstructing a model from a checkpoint

model.config() returns everything needed to rebuild: model_id, height_scale, predict_uncertainty, bins, bin_min, bin_max, htc. It exists in one place because three separate tools reconstruct a model from a checkpoint, and each used to hardcode the keys it knew about — adding the binned head would have broken all three silently. from_checkpoint() defaults htc to False for older checkpoints, because any checkpoint written before the head-tail cut existed was trained without it.

Part 5

The loss functions

Why the model predicts a distribution rather than a number, what each loss term buys, and the tests that prove the uncertainty head recovers a known answer.

5.1 The core objective — heteroscedastic Gaussian negative log-likelihood

L = 0.5 * ( log_var + (y - mu)^2 / exp(log_var) )

Read the two terms as a trade. The model can lower the residual term by admitting uncertainty — but it pays log_var for doing so. It cannot buy a free pass by predicting huge variance everywhere, because the first term grows.

Heteroscedastic means the uncertainty is predicted per pixel rather than being one number for the whole image. That is the useful version: a flat car park and a cluttered rooftop edge genuinely do not deserve the same error bar.

Predicting log-variance rather than variance keeps it positive without a clamp and keeps gradients well-scaled.

5.2 Every term in the composite loss

5.3 Clamps and guards

log_var range
Clamped to [−7, +7] (--log-var-max 7.0). Guards against exp() overflow and against the model escaping into “infinitely uncertain everywhere.”
Validity mask
Every loss takes a mask. LiDAR void pixels and no-data regions contribute nothing.
Gradient clipping
Norm clipped at 1.0 (--clip).
Rail tripwire
If log_var sits at its clamp for --rail-patience 50 consecutive steps, the run aborts. This is the guard that run05 did not have.
Sanity gates
A run is killed if RMSE exceeds --gate-rmse 25.0 or correlation falls below --gate-corr 0.20. tools/tripwire_selftest.py proves both that the tripwires fire on a broken run and that they do not fire on a healthy one.

5.4 The test that proves the uncertainty head works

Recovery of a known heteroscedastic sigma

A synthetic dataset is built with two regions of deliberately different noise: true σ = 0.50 in one and 3.00 in the other. The head is trained on it and asked what σ it thinks each region has. It recovers 0.497 and 2.99, and separates the two regimes with a ratio of 6.02 against a true ratio of 6.0.

This matters because “the model reports uncertainty” is a claim that is easy to make and hard to check on real data, where the true uncertainty is unknown. On synthetic data the true answer is known, and the head returns it.

Test suite status, run on 6 September 2026: tests/test_losses.py reports 19 passed, 0 failed. tests/test_gcp_affine.py reports all 9 tests passed, including exact recovery of a known ratio error — a fitted exponent of 1.3889 against a true 1.3889, with a residual root-mean-square of 7.74×10-7 m.

Both files must be run with PYTHONPATH set to the repository root; there is no pytest in the virtual environment, and each file carries its own __main__ runner.

5.5 Why uncertainty is a differentiator and not decoration

Single-view height is ill-posed. A model that outputs one confident number per pixel is hiding that fact. Three consequences make the uncertainty head worth its 33 parameters:

  • It scores in both halves of the marking scheme. It is an accuracy claim (“calibrated confidence”) and a visualisation feature (a display mode in the viewer).
  • It is operationally usable. The rank correlation between predicted σ and actual error is +0.829. Where the model says it is unsure, it is wrong, monotonically. That makes the uncertainty layer usable for triage — deciding which parts of an output need a human to look at them.
  • It feeds the measurement tool. A height difference between two clicked points carries an error bar derived from the two σ values, which is what turns a picture into an instrument.
